# 路线图 · v0.5 → v1.0

> 基线：**v0.4.0**（提交 `f0026a3`，已归档）
> 原则：**一次只做一件，每件都能独立验证、独立回滚。**
> 铁律：README 写明「游戏永远先能离线玩通」——任何新增 AI 能力，必须先回答
> **"AI 挂掉时游戏剩下什么"**。答不上来就不做。

---

## 排序依据

| 优先级 | 判断标准 |
|---|---|
| **P0** | 情感回报最高、落地风险最低、能用最小改动验证 |
| **P1** | 感知提升大但依赖 P0 产出 |
| **P2** | 需要前置条件全部就位 |

**关键决策：先做线索系统，不是先做 AI 导演。**
理由见 [`AI导演系统-评估与优化.md`](./AI导演系统-评估与优化.md)：线索系统是全篇唯一
**"固定脚本做不到、且不需要 AI 碰数值"** 的机制——情感回报最高、风险最低。
导演系统是"骨架"，但骨架**用代码就能搭**；线索系统是"灵魂"，
只有它能证明 AI 值得被接入。

## v0.5 — 线索系统 + 回响机制（P0）

**目标**：让"你在某刻做的选择，在多年后回响"。

### 任务

- [ ] **5.1 线索表状态**：在 `GAME_STATE` 新增 `threads: []`，字段补齐
      `id / seed / openedAt / lastTouchedAt / status / weight / echoCandidate / source / echoCount`
      - `source` 取值：`adventure` | `milestone` | `skipped` | `roast`
      - `echoCandidate`：一句可回响的素材（回响时喂给 AI）
      - `echoCount`：回响次数（防止同一个梗反复出现）
- [ ] **5.2 线索生成**：从**已有机制**派生，不新增系统
      - 奇遇里选了 A 没选 B → `"那条你没走的路"`
      - 里程碑选了"深耕优势" → `"被你放弃的短板，会在什么时候回来"`
      - 摸鱼被吐槽的一件事 → `"那次浪费的 N 天"`
      - 商品交互选「只是看看」→ `"你犹豫过的东西"`（依赖 6.3）
- [ ] **5.3 `echo` beat**：在现有事件节奏中新增独立 `echo` 类型
      **不给它独立类型，代码就管不住它**（它必须命中已有线索，而非生成新事件）
- [ ] **5.4 本地回响兜底**：无 BYOK 时用本地模板生成回响文案
      —— 回响**永远发生**，AI 只负责"把这一句讲得更像你"
- [ ] **5.5 冒烟测试**：线索开/闭/回响计数、echo 不重复命中、离线路径

**验收**
1. 无 Key、断网，能完整触发至少 3 次回响，文案来自本地模板
2. 同一线索不会被回响超过 2 次
3. `npm test` 全绿

**为什么先做**：如果这一件做出来效果好，再谈扩展；如果不好，省下后续 90% 的工作量。

## v0.6 — 派生年龄 + 人生阶段（P0）

**目标**：拿到"人生阶段"的全部感知收益，**只花约 30 行**。

> ⚠️ 核实结论：**当前代码里不存在"年龄"概念**——无 `age` 字段、无生辰、无岁时。
> 引入完整 Stage 状态机意味着 160 件商品全挂年龄门、结算 / 墓志铭 / 回放 / 成就全部加维度，
> 而玩家操作依然是"买 → 扣天数 → 买"，**玩法增量为零**。

### 任务

- [ ] **6.1 `inferAge()` 纯派生函数**（不存状态，纯粹算出来）
      ```js
      // 贪玩 → 时间飞逝；忙碌 → 时间变慢；养生 → 延缓
      const pace = 0.6 + funRatio * 1.2 - workRatio * 0.5 - cashRatio * 0.4;
      return Math.floor((30000 - remainingDays) / 400 * pace);
      ```
- [ ] **6.2 阶段文案表**（少年 / 而立 / 不惑 / 知天命）—— 进 prompt、进 UI
- [ ] **6.3 商品交互：「只是看看」** —— 一个 UI 小改，直接喂 5.2 的线索系统

**验收**：年龄显示随消费结构变化；阶段文案进 LLM prompt；无新状态字段落盘。

## 附带技术债（建议顺手处理）

- [ ] **默认 token 预算档位偏低**：`llm.js:19` 当前 `[50000, 200000, 1000000]`，
      默认 20 万。而"跨世收集 160 段人生"是核心长线玩法——
      **若单局 AI 消耗涨到 100K，默认预算只够 2 局**，用户第三次开局就撞上"额度用完"。
      任何提升 AI 用量的版本，都必须同步上调档位。
- [ ] **导演 tick 不能固定时钟**：15 分钟一局、交互间隔不到 10 秒，
      `setInterval(25s)` 会在玩家正在读商品描述时弹出 beat。
      触发条件应是"上次 beat 结束 + 玩家已连续 N 次操作 + 无未决弹窗"。
- [ ] **`.workbuddy/` 未加入 `.gitignore`**：属项目数据，不应入库。

## 已明确不做

| 不做 | 理由 |
|---|---|
| AI 决定数值 / 时机 | 违反铁律：AI 挂掉游戏必须还完整 |
| 独立 Stage 状态机 | 见 6.0——冗余，派生函数即可 |
| AI 生图做 NPC 头像 | 成本高、慢；改用 Prompt 生成视觉特征 → Canvas 程序化绘制 |
